# 文章循序渐进规范（PROGRESSION.md）—— 四阶段递进模型

> 核心要求：**文章像台阶，不是平铺**。读者从"认出问题"到"理解代价"到"会判断"到"知道下一步"——每一步都在上一步的基础上，缺一级就跳，读者就掉。
> 与其他规范分工：本文件=**行文递进**；article-writing-logic=**结构骨架**；ID-0001=**内容质量合同**；article-adversarial-checklist=**发布前审查**；ghostwriter=**空白 agent 评审**。

## 一、四阶段递进模型（每篇必含，顺序不可换）

```text
S1 认识    场景/问题：读者认出"这就是我"（具象时间/人/物）
    ↓ 衔接钩子："坏在哪？"
S2 理解    代价/原因：不解决的后果 + 为什么大家常踩（认知反转）
    ↓ 衔接钩子："那怎么选？"
S3 判断    方案/证据：3 步或对照，数字带来源与边界
    ↓ 衔接钩子："哪个适合我？"
S4 决定    选择/行动：选择阶梯 + 明确下一步（CTA 自然出现）
```

## 二、每阶段检查（发布前逐段跑）

| 检查 | 判定 |
|---|---|
| **承上** | 段首句是否引用上一段结论（"这还不是最糟的" / "所以第一步先看…"）？ |
| **启下** | 段末句是否给下一段留问题/钩子（"那么长度怎么定？"）？ |
| **信息密度** | 是否从"抽象感受→具体名词→数字→行动指令"递增？ |
| **术语渐进** | 新术语是否先通俗化再使用（"beam，就是船宽"）？ |
| **无跳级** | 没讲代价就直接给答案？= 跳级（禁止） |
| **边界一致** | S3/S4 的建议是否与全文边界声明一致（calm-water 指南不得给 open-water 建议）？ |
| **CTA 时机** | CTA 是否只在 S4 出现（读者有判断基础之后）？ |

## 三、递进词库（段间衔接用，避免生硬转折）

- 承上：这还不够 / 更麻烦的是 / 但真正的问题是 / 所以第一步先看…
- 启下：当然，这引出一个问题 / 那长度怎么定？ / 只剩最后一步…
- 反转：越……反而…… / 常识反了 / 九个首购者都会漏掉…
- 收束：一句话总结 / 现在把三个数字连起来…

## 四、反模式（一律禁止）

1. **先方案后痛点**——读者没意识到问题就得到答案（无代入）
2. **平铺并列**——"第一…第二…第三…"无因果递进（像目录不像文章）
3. **术语堆砌**——第 2 段就用 rocker/skeg 而没通俗化
4. **边界与建议打架**——说"不覆盖开放水域"却教人怎么选开放水域
5. **CTA 抢跑**——S1 就让你 "Get a Quote"（读者没判断基础）
6. **每段大而全**——一段讲完整个主题（违反"每段一个意图 ≤120 词"）

## 五、快速自检（5 问）

- [ ] 4 个阶段齐？顺序对？
- [ ] 每段首句承接上一段、末句引出下一段？
- [ ] 具体名词/数字/场景出现在每段？
- [ ] 术语都通俗化过？
- [ ] CTA 只在最后阶段且与边界一致？

## 六、机器检查入口

- `python3 interface-kit/writing/writing-module.py check <article.json>`（阶段顺序/承上启下词/术语渐进/边界/CTA 时机 5 项自动检查）
- `python3 interface-kit/site_pipeline.py audit <slug>` 已含绝对化/Markdown/单位等；进阶段检查用 writing-module
