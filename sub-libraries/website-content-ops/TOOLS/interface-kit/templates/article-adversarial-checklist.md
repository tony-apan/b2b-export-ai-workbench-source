# 文章对抗审查清单（发布前逐问，非空答才可发）

> 用法：每篇文章（含列表/详情页文案）发布前用本表自检；任一项答"否"→ 重写后再走发布。目标：**戳痛点、不空洞、可追溯**。

## A. 目标客群（写给谁）
- [ ] 一句话写清：（角色 + 场景）例："第一次买双人皮艇、周末湖上半天游的家庭"
- [ ] 文章开头 3 句内出现该角色的问题（不是"欢迎来到本博客"）
- [ ] 全文没有"面向所有人"的空泛句（如"很多人不知道……"无主体）

## B. 痛点（是否戳中，来源真实）
- [ ] 每篇至少 1 个**客户原话级痛点**（来源：customer-voice / 询盘 / 评论；无来源则标注 inferred 并写明推断理由）
- [ ] 痛点链完整：谁 → 触发场景 → 决策缺口 → 纠结/返工 → 后果 → 决策（ID-0001 六槽）
- [ ] 不编造痛点（无证据的"担心漏水"等必须降级为通用常识并标注）

## C. 证据与边界（防空洞/防编造）
- [ ] 每个数字/认证/交期声明绑定来源（source ID）或显式标注 synthetic demo
- [ ] 没有"最好的/销量第一/质量领先"等无法证明的最高级
- [ ] 没有暗示询盘/排名/转化结果的成功承诺（unsupported-outcome）

## D. 反"言之无物"（AI 敷衍检测）
- [ ] 删除本篇后读者是否毫不可惜？（自问：有什么是网上搜不到、只有这里有的？）无 → 补差异化
- [ ] 每段有且仅有 1 个核心意思；无"空话连篇"段（全段无具体名词/数字/场景）
- [ ] 决策工具是否落地（清单/对照表/决策卡，而非"建议咨询专业人士"）

## E. SEO 与结构（ID-0002 契约）
- [ ] title ≤60 字；meta description 150-160 字（任务/证据/下一步）
- [ ] 正文从 H2 开始、不跳级；唯一 H1 由 CMS 生成
- [ ] slug 短而可读；关键词自然地出现在标题/H1/H2/首段（不堆砌）
- [ ] 语言与目标市场一致（B2B 出口 → 买家语言，非自嗨营销词）

## F. 发布前自动化门
- [ ] `python3 writing/writing-module.py check <article.json>` 渐进+格式检查通过（6 项；缺 S1/S4 仅软提示）
- [ ] 正文块类型全为服务器原生词法 `p|h2|h3|blockquote`（heading/paragraph 旧词法禁用；未验证块勿用，见 FORMAT-SPEC）
- [ ] residue gate（模板词）pass；空态扫描 = 0
- [ ] readback diff 仅无害回填
