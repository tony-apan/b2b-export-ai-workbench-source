# 文章创作逻辑（通用方案）—— 软文大神文案逻辑总结 + 对抗升级

> 定位：**创作侧**逻辑（怎么写）——与 ID-0001（审查合同：六槽 pain chain/证据/禁声明）和 article-adversarial-checklist（发布前检查）配合使用：  
> **逻辑出稿 → 空白子 agent 完善 → checklist 验收 → gate 发布**。文章含任何"视觉/列表/图"请遵守 MODULES 三·五 Slate 矩阵。

## 一、三层目标（动笔前默念）
1. **行动**：读者看完知道/想做一件事（选型对比/联系/下单）
2. **信任**：每句都有来源/细节/数字（无来源=删或标 demo）
3. **记忆**：至少一句能被记住的话（钩子/金句）

## 二、六段式骨架（正文从 H2 开始，循序渐进、代入感、留钩子）

```
【标题】钩子公式（见钩子库），勿剧透全答案
【引言 3-5 句】场景代入（具体时间/人/物）→ 痛点一句（客户原话级）→ 本文承诺（"10 分钟帮你选"）
  —— 3 秒内让读者确认"写的就是我"
① H2 痛点现实：画面感场景 + 1 句原话级痛点（来源 customer-voice）
② H2 代价与后果：不解决的具象代价（钱/时间/尴尬/返工——Agitate，用细节不用形容词堆）
③ H2 真相/原因：为什么大家常踩（认知反转——读者想看下去）
④ H2 方案与证据：3 步或对照表，每个数字带来源；只说能证明的
⑤ H2 选择阶梯：不同人不同选（为产品立身位，也是差异化）
⑥ H2 收尾行动：一句金句总结 + 明确 CTA（一句，不啰嗦）
```
**层次规则**：H1=CMS 标题（唯一）；正文从 **H2 开始**；H2 不跳级；**每段 ≤120 词、只讲一个意图**；段与段有过渡句（"这还不是最糟的……所以第一步先看……"）；顺序不可换（痛点→代价→原因→方案→阶梯→行动），先讲方案后讲痛点=无效。

## 三、钩子库（标题/段间/结尾各取所需）
| 钩子 | 示例 | 位置 |
|---|---|---|
| 场景 | "周一早 7 点，两个防水袋塞进座舱……" | 引言/段间 |
| 问句 | "4.2 米和 5.2 米，差别只是一米吗？" | 标题/过渡 |
| 数字 | "68cm 的梁高，让第一次没翻" | 标题/①② |
| 反转 | "越稳的船，越容易到得快" | ③（真相段） |
| 身份 | "第一次买双人皮艇的人，都问这三件事" | 标题/引言 |
| 悬念 | "第三个检查，九成人会漏掉" | 段间钩子 |
| 承诺 | "看完这篇，十分钟选对型号" | 引言/收尾 |

## 四、代入感三件套（每段至少一件）
- **第二人称**：你/你们；别写"很多人不知道"（无主体）
- **具象时空**：周五傍晚的湖、两个 45L 防水袋、14 天通勤测试——不用"一些情况下"
- **冲突细节**：湿透的帆布包/翻不到护颚的尴尬/装车 25 分钟的抱怨

## 五、防空洞自检（发布前逐段问）
- [ ] 删掉这段，读者损失什么？（答不上=删）
- [ ] 段里有具体名词/数字/场景？（全抽象=重写）
- [ ] 每段有结论/落点（不要"事实上……"结尾）
- [ ] 整篇只有 1 个 CTA 主题（不要又订阅又咨询又对比）
- [ ] 金句是否独一无二（"品质保障"这类空话不算钩子）

## 五·三·五、评审六轮沉淀（2026-08-29）
- **先答案后故事**：H1 → 一句话适用场景 → Quick Answer → 三参数 → （故事/引言后置）——搜索用户先要判断方法
- **标题-内容对齐**：标题必须包含适用边界词（如 "for Calm Water"）+ 数量承诺（3 Specs）；内容多出的项（fit checks）在首段声明归类；slug 不轻易改
- **作者段（真实主体）**："Written by <真实团队>. Reviewed against <产品规格表>. Last updated: <日期>. Specifications refer to <产品> listing and should be confirmed before purchase."——不得虚构专家姓名
- **技术措辞模型**：用 "can/may/tend to + 依赖因素列出" 替代 "always/usually/comfortable default"；每结论带 2-3 个影响因素（hull shape/rocker/load/wind）
- **对照信息**：平台表格 ❌ → 文本对照行（What it affects: … · What to check: …）

## 五·四、专业决策页增强（评审采纳，参考 visual-design-rules.md）
- **Quick Answer 三数字总览**：文首 1 个 QUICK ANSWER callout（三数字+边界声明"参考值/以厂家为准"）
- **承重公式化**：Total = paddler1+2+gear+food+water+safety；给 1 个数字示例（如 80+65+25=170kg）
- **绝对化戒律**：禁用"足够/稳定/最多"裸断言——句尾必带边界（参考值/该产品规格/以厂家为准/水域条件）
- **图片来源可见**：文末 callout Photo credit（作者+许可）——不只在 alt
- **CTA 真链接**：正文只自然语言指路；**真链接=详情页模板模块**（产品推荐/contact 模块渲染真 <a>）
- **标题 SEO 化**：格式 "How to Choose a X: N Specs to Check | 品牌"（意图词前置；H1 与 title 一致；slug 不轻易改）

## 五·五、正文格式规则（平台矩阵：以公网渲染为准）
- **正文标题用原生 h2/h3**（`{"type":"h2","children":[{"text":"..."}],"id":"..."}`，服务器原生词法，渲染 slate-h2 大标题；heading/paragraph 旧词法已禁用）；bold 仅用于关键数字/结论强调，不再替代标题
- 关键数字/结论**加粗**（5.2m / 68cm / 220kg）；斜体、下划线可选（均验证支持）
- **禁止 Markdown 语法**（`[text](url)`/`**x**`/`# 标题`）——原样显示成文本！
- **CTA 用自然语言**（"Browse the Demo Product in our catalogue, or send us your trip plan"），链接只进模块字段
- 发布前自检：正文无 `](`、无 `#`、无 `*` 加粗残留；strong 数 >0（有加粗应用）

## 六、空白子 agent 完善流程（其他 AI 执行标准动作）
```text
① 按本文档出初稿（六段式+钩子+代入感）
② 派 1 个空白子 agent（prompt 模板：templates/ghostwriter-review-prompt.md；
   只给它文章+本逻辑，不给会话上下文）——要求：逐段评分(代入/钩子/层次/空洞 1-5)+
   最弱 3 处改写示例+钩子缺失检查
③ 合并其建议（只改表达方式；**不得添加未提供的事实/数字**——如有需要，回资料补充）
④ 发布前跑 article-adversarial-checklist + validate_slate_content_shape + gate
```
> 子 agent 与主 AI 毫无上下文共享 → 天然防"自说自话"；它的评分即"读者视角"模拟器。
