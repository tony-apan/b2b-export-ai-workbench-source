# 建站前置资料收集清单（客户输入模板）

> 用途：承接客户/用户建站请求时，第一步向用户收集以下资料。**缺项 = 阻塞**（可先建骨架，但发布前必须补齐）。
> AI 应将本清单作为"前置检查"固化进流程：收到建站需求 → 先发本清单 → 收集完 → 再动工。

## 〇、🔑 平台账号凭据（最先要，没有它 AI 无法开工）

> ⚠️ **这是第 0 项、最高优先级**：技术流程第 0 步就要求"凭据就绪"——**没有凭据 = 全链路阻塞**，先于一切资料收集。
> AI 收到建站需求后，**第一句话**就用下面的模板向用户索要（照抄发给用户即可）：

```text
🔑 开工前请提供建站平台的登录账号（二选一）：

👍 ① 直接把「邮箱 + 密码」发给我（推荐 · 最快）
   我登录一次就开工。密码本身我不会存进任何文件。

② 如果你不想发密码，也可以自己拿一张"临时通行证"发我：
   用电脑 Chrome 打开后台网址并登录 → 按键盘 F12（会弹出一个技术面板，别慌，不用看懂）
   → 点面板顶部的「应用 / Application」→ 左侧点「Cookie」
   → 在列表里找到名字叫 payload-token 的一行 → 双击它的值 → 全选复制发我。
   💡 这一串很长（一百多个字符），复制时从头拖到尾别漏。

❓ 觉得 ② 太麻烦？直接用 ① 就行。
❓ 还没有账号？直接回我一句"没有账号"，我帮你安排开通。
```

| 检查项 | 说明 |
|---|---|
| 平台账号（邮箱+密码）**或** payload-token | 见上方模板；**只在本次对话临时使用**，不写文件不进记录不公开 |
| 用户无账号 | 引导开通（回复"没有账号"后走 [CONTACT.md](../../../CONTACT.md) 流程），AI 不得自行注册或跳过登录 |

## 〇-a、🗣️ 对用户说话规则（硬性约束，每句话过一遍这个表）

> 用户群体画像：**做外贸的中小老板，三四十岁女性居多，不懂技术**。
> AI 对用户说的每一句话都必须让这个画像的人一眼看懂。内部术语一律禁止直出——用右列的白话替代：

| ❌ 内部黑话（禁止对用户说） | ✅ 白话（照这个说） |
|---|---|
| 建任务目录 / 客户任务区 / 放公开仓库外 | 我把你的资料单独安全存放，和公开内容完全隔离 |
| 防客户资料入库 / 提交 / 入库 | 保证你的资料不会被公开、不会外泄 |
| 跑注册表校验 / 校验 / gate / 检索 | 检查一遍工具是否正常、是不是最新版 |
| 历史坑检索 / find / issues | 查一下之前建站踩过的坑，避免同样问题再发生 |
| ISS-xxx 编号 / BOUNDARY / canonical / ledger / digest / readback / 回读 / CDN / RSC / chunk / action id / payload / manifest / slug | **一律不出现**。翻译成后果：「这是平台自带的行为」「我已经核对过无误」 |
| 环境变量 / WS_TOKEN / WS_EMAIL | 只在这次对话里临时使用，不会留下 |
| token / 令牌 | 访问通行证（相当于一张临时门禁卡） |
| capability / deployment / fingerprint | 平台当前状态 / 平台版本信息 |
| DNS / 解析 | 域名指向设置（在域名服务商的"解析设置"里改） |
| CNAME / 记录 | "域名指向"的一种设置方式 |
| 记录值 / Target | 你要填进去的那串地址（我会直接给你） |
| brief / brief.json / 内容规划表 | 你的网站内容方案 |
| 对账 / readback / 核对 | 我再核对一遍 |
| 冒烟 / dry-run / 演练 | 先空跑一遍试试，不动真格 |
| BLOCK / gate 拦截 | 这一步必须先解决，卡住了 |
| synthetic / 合成内容 / demo | 示例内容（不是真实信息，已明确标注） |
| 部署 / deploy / 上线 | 让网站正式能访问 |
| 复审 / 审查门 / review record | 我会再检查一遍内容质量 |

**反面案例**（真实发生，AI 临场汇报说了黑话）：
> ❌ 「现在建客户任务目录（放在公开仓库外，防客户资料入库），跑注册表校验和历史坑检索。」
> ✅ 「接下来我把你的资料单独安全存放（不会对外公开），然后检查一遍工具是否为最新版，并查一下之前建站踩过的坑，避免同样的问题再发生。」

**检查方法**：发给用户的每一段话，想象目标读者（如「36 岁做假发的义乌外贸 SOHO 张姐」）在微信里读到——任何一句她要停下来想"这是啥"，就重写。
**诚实性红线**（承诺必须能兑现）：
- 只说"密码不存进文件"，不说"用完就什么都不剩"——登录通行证在过期前一直有效；
- 不说"聊天记录里不会有"——聊天窗口本身会留底，正确做法是引导用户完工后改密码；
- 不说"改密码后立刻失效"——平台行为未验证，只说"更稳妥"。

**发送前硬规则**：逐句自查，出现连续 3 个以上英文字母（网址除外）＝不过关，回对照表重写。

**唯一例外（控制台字面控件名）**：当 AI 需要指导客户在 DNS 服务商控制台里**照着点**时，控件名（如 `Type`/`Name`/`Target`/`Records`/`Save`、服务商界面上的 `CNAME`/`DNS`）必须**原样引用**——客户要在界面上找到同样的字。此时用引号框住并加一句说明：「引号里的字是控制台上要照着点的，其他部分我都用大白话讲」。


## 〇-b、📣 建站全链用户交互话术（AI 照抄模板，emoji 已突出关键项）

> 凭据只是开始。以下模板覆盖从开工到交付后跟进的全链，AI **照抄方括号内的结构**，方括号里的提示词发送前必须全部替换成真实值——**一条 `[...]` 都不能剩**。站点数不足/超出模板行数时按实际增删，序号顺延。

**① 登录成功 · 选站确认**（多站点时必须让用户确认，不得自行选；两个站名字一样时，让用户用浏览器打开网址辨认）
```text
✅ 已登录成功。
发现 [数量] 个站点：
  1️⃣ [站点名]（网址：[网址]）
  2️⃣ [站点名]（网址：[网址]）
👉 请确认要操作哪个站点？（回复序号即可；两个名字一样的话，把网址在浏览器里打开看一眼再告诉我）
```

**② 资料收齐确认 · 开工前最后确认**
```text
📋 资料已收齐，开工前最后确认：
  站点类型：[新站 / 改现有站]
  内容规模：产品 [数量] 个、文章 [数量] 篇
  大概要 [一段时间区间]，中间我会随时汇报进度
  👉 网站正式上线前，我会先问过你
确认后我就开工。
```

**③ 阶段进度汇报**（每完成一个大步骤发一条，让用户知道 AI 在干活）
```text
🔄 [步骤名]完成：
  ✅ [已完成的事，用结果说话，如：40 张图片全部压缩成打开更快的格式]
  ✅ [已完成的事，如：每张图都配了能让谷歌搜到你的文字说明]
  ⏳ 接下来：[下一步动作]
```

**④ ⛔ 阻塞/需要用户决策时**（不要默默等待，说清卡在哪、要什么）
```text
⛔ 卡在：[具体环节]
原因：[一句话]
👉 需要你：[精确的选项 A/B 或资料项]
```

**④-b 👉 发布批准**（兑现"上线前问你"的承诺——发布前必须发这条并等到明确同意）
```text
👉 网站内容我都做好了，准备正式上线。
上线后任何人都能访问，内容也不会再悄悄改动。
确认上线请回「上线」；还想改哪里，直接告诉我。
```

**④-c ⛔ 删除/不可逆操作授权**（删站/删内容/清数据前必须发这条并等到明确同意）
```text
⛔ 需要你确认一个不能撤销的操作：
我准备删除：[删什么，逐项列清楚]
删了就找不回来。确认删除请回「确认删除」；不确定就回「先别删」。
```

**④-d 示例内容授权**（资料不够、需要放示例内容时）
```text
👉 有 [数量] 处内容我手里的资料不够，两个办法：
  A. 你补给我（文字/图片都行）
  B. 我先放一段标注清楚的示例内容，上线前你随时换掉
选哪个？
```

**④-e 🔑 凭据中途失效**（长任务中登录过期时）
```text
🔑 平台的临时通行证过期了，需要你再给我一次（和开工时一样）：
最简单：把邮箱和密码再发我一次（我不会保存）；
或者照之前的方法重新拿一张"临时通行证"。
```

**⑤ 🎉 交付验收**（链接 + 编号动作清单 + 白话已知事项；已知事项禁止内部编号和术语）
```text
🎉 网站已完成并上线！
🔗 网站地址：[网址]
✅ 请帮我检查这 3 件事（每件 1 分钟）：
  1. 电脑上把首页、产品、文章、联系页各点开一遍
  2. 在联系页发一条测试询盘，看你的邮箱收不收得到
  3. 用手机打开网站，看看排版有没有乱
⚠️ 已知事项（平台自带的小限制，不影响客人浏览和询盘，不用处理）：
  · [如：网页标题会自动带上平台后缀——平台统一行为]
  · [如：个别浏览器标签页的描述由平台控制]
发现任何问题直接发我，我马上处理。
```

**⑥ 🔒 收尾提醒**（每次会话结束）
```text
🔒 收尾提醒：今天的工作完成了！旧密码在聊天里出现过，建议你现在就去后台改一个新密码，更稳妥。
```

**⑦ 👋 交付后跟进**（3 天后或待补内容催收时，可选）
```text
👋 网站上线 3 天啦。后台收到询盘了吗？
之前留的 [待补内容] 有空补给我，我随时帮你更新上去。
```

## 〇-c、🌍 域名话术模板（建站完成后使用，ISS-147）

> **时机**：网站做好、客户看过满意之后。**不要在开工时就谈域名**——先交付价值再谈配置。
> 四条模板覆盖：没域名→购买引导；有域名→绑定确认；不会配→按 NS 商指引；配好了→验证反馈。

**① 客户没有域名 · 购买引导**
```text
🌍 网站已经做好啦！接下来给它配个专属网址（域名），这样客户就能用你自己的网址访问。

两个选择：
👍 推荐 Cloudflare（cloudflare.com，约 10 美元/年，以官网实时价为准）
   ✅ 不用实名，开通快   ⚠️ 需要 PayPal 或支持外币的信用卡
2️⃣ 或者阿里云（aliyun.com，约 85 元/年）
   ✅ 支付宝就能付、国内速度快   ⚠️ 需要实名认证

做外贸用哪个都行，做外贸的域名不需要备案。
选好了告诉我，我帮你把网站接上。
```

**② 客户已有域名 · 绑定确认**
```text
🔍 你说的是 [域名] 对吧？我查了一下：
   ✅ 域名存在，注册时间是 [年份]
   [如果是本人购买] 我把它接到你的网站上，需要你确认一下——这个域名是你自己购买的吗？

确认后我就接入，然后教你怎么设置（大概 3 分钟）。
```

**③ 客户不会配置 DNS · 按服务商给指引**
```text
🔧 你的域名用的是 [服务商名]，我们这样操作（3 分钟）：

[按 NS 服务商贴对应步骤，见下]

弄好告诉我一声，我立刻帮你检查是否生效。
```
- **Cloudflare 用户**（`*.ns.cloudflare.com`）：
  ```text
  1. 打开 dash.cloudflare.com 登录 → 点你的域名
  2. 左边菜单点「DNS」→「Records」→ 点「Add record」
  3. 这样填：
     Type 选 CNAME
     Name 填 www
     Target 填 [站点运行时域名]
     Proxy status 点成灰色云朵（DNS only，重要！）
  4. 点 Save
  ⚠️ 根域名（@）先不用管——Cloudflare 对根域名不支持这种接法，
     我会帮你设置成"输 [客户域名] 自动跳到 www.[客户域名]"，效果一样。
  ```
- **阿里云用户**（`*.alidns.com` / `*.hichina.com`）：
  ```text
  1. 打开阿里云「云解析 DNS」控制台 → 找到你的域名 → 点「解析设置」
  2. 点「添加记录」，加两条：
     第一条：记录类型 CNAME，主机记录 www，记录值 [站点运行时域名]
     第二条：记录类型 CNAME，主机记录 @，  记录值 [站点运行时域名]
  3. 保存即可
  ```

**④ 配置完成 · 验证反馈**（三档状态，按 `certificateStatus` 实际值选一，**不得**把 failed 说成已生效）
```text
✅ 域名已经接上，我帮你检查过了：
   ✅ 解析正确

[证书已生效时]
   ✅ SSL 安全证书已生效，网站可以正常访问
[证书申请中时]
   ⏳ 安全证书正在申请，一般几分钟内完成，稍后我再帮你确认
[证书失败时]
   ⚠️ 解析已正确，安全证书还在等平台签发（这一步由平台自动完成，不需要你操作）
      我会盯着，签好第一时间告诉你

🔗 现在可以用这个网址访问你的网站了：https://[域名]
建议你在手机上再打开看看效果。
```

## 一、必填基础（5 项，缺一不可）

| # | 资料 | 用途 | 缺失影响 |
|---|---|---|---|
| 1 | **公司名称 / 品牌名称** | 站名、导航品牌、footer、title 前缀 | 无法命名站点 |
| 2 | **用户昵称 / 职位** | About 页团队卡、表单署名、卖家身份 | About/Team 无内容 |
| 3 | **联系方式：邮箱 + 电话 + WhatsApp** | 联系页、表单通知（**邮箱必须真实可收件**）、浮钮 | 表单链路不可用 |
| 3b | **地址 + 营业时间 + 社媒账号**（可选但推荐） | 联系页信息卡/地图/页脚 | 缺失时地址/坐标保留 demo 并在交付清单标注'待用户提供' |
| 4 | **地址**（含国家/城市） | 联系页信息卡、地图坐标（可另给 lat/lng 或地名） | 联系页不完整 |
| 5 | **产品资料 / 公司资料文件**（PDF/DOCX/PPT/网页/图片/口述） | 建站内容唯一事实源；AI 解析成 Markdown 后提炼 | 无法产出真实内容 |
| 5c | **素材推进策略（AI 先做，最后才问用户）**：①从现有资料/站内/公开信息**自动提炼**（规格/卖点/案例/痛点，标注 inferred）→ ②提炼不足时**给出方案**（demo 占位+标注/或结构化提问）→ ③仅剩无法推断的才**索要用户** | 不把"能自己做"的变成"用户负担" | 素材缺口分级：缺失=先推→再问 |
| 5b | **数量要求（美观基线）**：**产品 ≥3、文章 ≥4** | 列表页网格/首页模块/相关推荐区不空不稀（CONTENT-MINIMUM.md） | 数量不足 → gate BLOCK，需用户补充或接受 demo 占位 |

## 二、资料解析与提炼流程（AI 侧，收齐后执行）

```text
① 资料解析：PDF/DOCX/网页 → Markdown（调用宿主解析能力，保留来源/页码/章节定位）
② 事实抽取：公司名/品牌/标语/产品/规格/认证/联系方式……每条标注 confirmed/inferred/missing
③ 内容规划：对照「建站必备内容清单」(site-content-checklist.md) 逐项映射
④ 缺口清单：客户补充（或授权 demo 占位并记录）
⑤ brief.json 落地 → site_pipeline.py validate → 开始建站
```

## 三、版权与合规（收集素材时）

- 产品图：客户自有图最佳；否则 Wikimedia/CC 图需记录 author+license（项目有 manifest 模板）
- 文案：客户资料原文可直接引用；AI 合成的示例内容必须显式标注（synthetic demo），不冒充真实案例/销量/认证

## 四、开工前用户确认点

- [ ] 确认站点名称与 URL slug 偏好
- [ ] 确认 demo 值（电话/地址/社媒）可接受，或提供真实值
- [ ] 确认图片授权方式（自有/代找 CC）
- [ ] 确认首批内容范围（1 产品 2 文章起步 / 更多）

> 模板用法：交付给用户前先发「一、必填基础」表格收集；「二」由 AI 执行；「三/四」在动工前与用户对齐一次。


## 五、联系方式替换流程（用户提供后必做）
1. 收集：邮箱/电话（含区号格式 +86 x xxxx xxxx）/WhatsApp（wa.me/86xxxxxxxxx）/地址/坐标/社媒
2. 替换：contact 页（info 卡 items + 表单卡双字段）+ 首页 contact 模块 + **全站 globals 浮钮/弹窗**（7 页重交）（弹窗元素必带 anchorId=header CTA 锚点名，见 customization-checklist 26b / ISS-094）
3. 验证：`python3 site_pipeline.py contact <slug> --real "<真实值|分隔>"` → PASS；公网人工核对显示格式
4. 未提供项：保留 demo 但写入交付清单'待用户提供'清单（不得静默交付）

## 六、写作前置素材（写文章前"先要"，缺下面任何一项=不能写有代入感的文章）
| # | 素材 | 作用 | 缺失方案 |
|---|---|---|---|
| 1 | **客户原话/询盘/评论片段**（至少 3 条） | 痛点句与代入感来源（customer-voice） | 无 → 只能写通用介绍+明确标注 demo，仍须先索要 |
| 2 | **真实数据/规格**（每文章 2-3 个数字） | ①②④ 段证据 | 无法证明的数字=删除 |
| 3 | **真实案例或名片**（客户类型/场景） | ⑤ 阶梯与信任 | 无 → 用中性场景（不编案例） |
| 4 | **图片**（每篇 1 封面+可选 1 正文） | 封面图/代入感 | 缺 → 代找 CC 素材（记录 license） |
| 5 | **目标客群描述**（角色+场景一句话） | 全文人称与钩子选择 | 无 → 文章=无的放矢，先问 |
