# 建站前置资料收集清单（客户输入模板）

> 用途：承接客户/用户建站请求时，第一步向用户收集以下资料。**缺项 = 阻塞**（可先建骨架，但发布前必须补齐）。
> AI 应将本清单作为"前置检查"固化进流程：收到建站需求 → 先发本清单 → 收集完 → 再动工。

## 〇、🔑 平台账号凭据（最先要，没有它 AI 无法开工）

> ⚠️ **这是第 0 项、最高优先级**：技术流程第 0 步就要求"凭据就绪"——**没有凭据 = 全链路阻塞**，先于一切资料收集。
> AI 收到建站需求后，**第一句话**就用下面的模板向用户索要（照抄发给用户即可）：

```text
🔑 开工前请提供建站平台的登录凭据（二选一）：

👍 ① 直接把「邮箱 + 密码」发给我（推荐 · 最快 · 全自动）
   我会登录一次自动提取访问令牌，密码用完即弃，不会存进任何文件或仓库。

② 或者你自己在浏览器登录后台后，把访问令牌发给我：
   登录 https://workspace.laicms.com → 按 F12 打开开发者工具
   → Application（应用）→ Cookies → 找到 payload-token → 复制它的值发我。

   🔒 安全承诺：凭据只在这次对话里临时使用，不写进任何文件、不会对外公开、也不会出现在记录里。
      完成后建议你在后台改一次密码，让刚才的登录信息立刻失效。

❓ 还没有账号？告诉我，走开通流程（见 [CONTACT.md](../../../CONTACT.md)）。
```

| 检查项 | 说明 |
|---|---|
| 平台账号（邮箱+密码）**或** payload-token | 见上方模板；**只在本次对话临时使用**，不写文件不进记录不公开 |
| 用户无账号 | 引导走 [CONTACT.md](../../../CONTACT.md) 开通流程，AI 不得自行注册或跳过登录 |

## 〇-a、🗣️ 对用户说话规则（硬性约束，每句话过一遍这个表）

> 用户群体画像：**做外贸的中小老板，三四十岁女性居多，不懂技术**。
> AI 对用户说的每一句话都必须让这个画像的人一眼看懂。内部术语一律禁止直出——用右列的白话替代：

| ❌ 内部黑话（禁止对用户说） | ✅ 白话（照这个说） |
|---|---|
| 建任务目录 / 客户任务区 / 放公开仓库外 | 我把你的资料单独安全存放，和公开内容完全隔离 |
| 防客户资料入库 / 提交 / 入库 | 保证你的资料不会被公开、不会外泄 |
| 跑注册表校验 / 校验 / gate / 检索 | 检查一遍工具是否正常、是不是最新版 |
| 历史坑检索 / find / issues | 查一下之前建站踩过的坑，避免同样问题再发生 |
| ISS-xxx 编号 / BOUNDARY / canonical / ledger / digest / readback / 回读 / CDN / RSC / chunk / action id / payload / manifest / slug | **一律不出现**。翻译成后果：「这是平台自带的行为」「我已经核对过无误」 |
| 环境变量 / WS_TOKEN / WS_EMAIL | 只在这次对话里临时使用，不会留下 |
| token / 令牌 | 访问通行证（相当于一张临时门禁卡） |
| capability / deployment / fingerprint | 平台当前状态 / 平台版本信息 |
| 复审 / 审查门 / review record | 我会再检查一遍内容质量 |

**反面案例**（真实发生，AI 临场汇报说了黑话）：
> ❌ 「现在建客户任务目录（放在公开仓库外，防客户资料入库），跑注册表校验和历史坑检索。」
> ✅ 「接下来我把你的资料单独安全存放（不会对外公开），然后检查一遍工具是否为最新版，并查一下之前建站踩过的坑，避免同样的问题再发生。」

**检查方法**：发给用户的每一段话，想象目标读者（如「36 岁做假发的义乌外贸 SOHO 张姐」）在微信里读到——任何一句她要停下来想"这是啥"，就重写。

## 〇-b、📣 建站全链用户交互话术（AI 照抄模板，emoji 已突出关键项）

> 凭据只是开始。以下 6 个交互点覆盖从开工到交付的全链，AI **照抄模板**，方括号内替换实际值。

**① 登录成功 · 选站确认**（多站点时必须让用户确认，不得自行选）
```text
✅ 已登录成功。
发现 [N] 个站点：
  1️⃣ [站点名]（[域名]）
  2️⃣ [站点名]（[域名]）
👉 请确认要操作哪个站点？（回复序号即可）
```

**② 资料收齐确认 · 开工前最后确认**
```text
📋 资料已收齐，开工前最后确认：
  站点类型：[新站/改现有站]
  内容规模：产品 [N] 个、文章 [N] 篇
  预计耗时：约 [X] 分钟
  ⚠️ 发布动作会等你最后批准
确认后我就开工。
```

**③ 阶段进度汇报**（每完成一个大步骤发一条，让用户知道 AI 在干活）
```text
🔄 [步骤名]完成：
  ✅ [已完成的关键项 1]
  ✅ [已完成的关键项 2]
  ⏳ 接下来：[下一步动作]
```

**④ ⛔ 阻塞/需要用户决策时**（不要默默等待，说清卡在哪、要什么）
```text
⛔ 卡在：[具体环节]
原因：[一句话]
👉 需要你：[精确的选项 A/B 或资料项]
```

**⑤ 🎉 交付验收**（给用户可点的链接 + 验收清单 + 已知事项）
```text
🎉 网站已完成并发布！
🔗 预览地址：[displayDomain URL]
✅ 验收清单：
  [ ] 首页/产品/文章/联系页逐页打开
  [ ] 表单提交一封测试询盘
  [ ] 手机端打开检查排版
⚠️ 已知事项（平台自带的小限制，不是网站的问题，不影响使用）：
   · 网页标题会自动带上平台后缀（平台统一行为）
   · 个别浏览器标签页描述由平台控制
   （用大白话描述，不写内部编号和术语）
```

**⑥ 🔒 收尾提醒**（每次会话结束）
```text
🔒 收尾提醒：今天的工作完成了！建议你抽空到后台改一次密码——这样刚才给我的登录信息就自动失效了，最安全。
```

## 一、必填基础（5 项，缺一不可）

| # | 资料 | 用途 | 缺失影响 |
|---|---|---|---|
| 1 | **公司名称 / 品牌名称** | 站名、导航品牌、footer、title 前缀 | 无法命名站点 |
| 2 | **用户昵称 / 职位** | About 页团队卡、表单署名、卖家身份 | About/Team 无内容 |
| 3 | **联系方式：邮箱 + 电话 + WhatsApp** | 联系页、表单通知（**邮箱必须真实可收件**）、浮钮 | 表单链路不可用 |
| 3b | **地址 + 营业时间 + 社媒账号**（可选但推荐） | 联系页信息卡/地图/页脚 | 缺失时地址/坐标保留 demo 并在交付清单标注'待用户提供' |
| 4 | **地址**（含国家/城市） | 联系页信息卡、地图坐标（可另给 lat/lng 或地名） | 联系页不完整 |
| 5 | **产品资料 / 公司资料文件**（PDF/DOCX/PPT/网页/图片/口述） | 建站内容唯一事实源；AI 解析成 Markdown 后提炼 | 无法产出真实内容 |
| 5c | **素材推进策略（AI 先做，最后才问用户）**：①从现有资料/站内/公开信息**自动提炼**（规格/卖点/案例/痛点，标注 inferred）→ ②提炼不足时**给出方案**（demo 占位+标注/或结构化提问）→ ③仅剩无法推断的才**索要用户** | 不把"能自己做"的变成"用户负担" | 素材缺口分级：缺失=先推→再问 |
| 5b | **数量要求（美观基线）**：**产品 ≥3、文章 ≥4** | 列表页网格/首页模块/相关推荐区不空不稀（CONTENT-MINIMUM.md） | 数量不足 → gate BLOCK，需用户补充或接受 demo 占位 |

## 二、资料解析与提炼流程（AI 侧，收齐后执行）

```text
① 资料解析：PDF/DOCX/网页 → Markdown（调用宿主解析能力，保留来源/页码/章节定位）
② 事实抽取：公司名/品牌/标语/产品/规格/认证/联系方式……每条标注 confirmed/inferred/missing
③ 内容规划：对照「建站必备内容清单」(site-content-checklist.md) 逐项映射
④ 缺口清单：客户补充（或授权 demo 占位并记录）
⑤ brief.json 落地 → site_pipeline.py validate → 开始建站
```

## 三、版权与合规（收集素材时）

- 产品图：客户自有图最佳；否则 Wikimedia/CC 图需记录 author+license（项目有 manifest 模板）
- 文案：客户资料原文可直接引用；AI 合成的示例内容必须显式标注（synthetic demo），不冒充真实案例/销量/认证

## 四、开工前用户确认点

- [ ] 确认站点名称与 URL slug 偏好
- [ ] 确认 demo 值（电话/地址/社媒）可接受，或提供真实值
- [ ] 确认图片授权方式（自有/代找 CC）
- [ ] 确认首批内容范围（1 产品 2 文章起步 / 更多）

> 模板用法：交付给用户前先发「一、必填基础」表格收集；「二」由 AI 执行；「三/四」在动工前与用户对齐一次。


## 五、联系方式替换流程（用户提供后必做）
1. 收集：邮箱/电话（含区号格式 +86 x xxxx xxxx）/WhatsApp（wa.me/86xxxxxxxxx）/地址/坐标/社媒
2. 替换：contact 页（info 卡 items + 表单卡双字段）+ 首页 contact 模块 + **全站 globals 浮钮/弹窗**（7 页重交）（弹窗元素必带 anchorId=header CTA 锚点名，见 customization-checklist 26b / ISS-094）
3. 验证：`python3 site_pipeline.py contact <slug> --real "<真实值|分隔>"` → PASS；公网人工核对显示格式
4. 未提供项：保留 demo 但写入交付清单'待用户提供'清单（不得静默交付）

## 六、写作前置素材（写文章前"先要"，缺下面任何一项=不能写有代入感的文章）
| # | 素材 | 作用 | 缺失方案 |
|---|---|---|---|
| 1 | **客户原话/询盘/评论片段**（至少 3 条） | 痛点句与代入感来源（customer-voice） | 无 → 只能写通用介绍+明确标注 demo，仍须先索要 |
| 2 | **真实数据/规格**（每文章 2-3 个数字） | ①②④ 段证据 | 无法证明的数字=删除 |
| 3 | **真实案例或名片**（客户类型/场景） | ⑤ 阶梯与信任 | 无 → 用中性场景（不编案例） |
| 4 | **图片**（每篇 1 封面+可选 1 正文） | 封面图/代入感 | 缺 → 代找 CC 素材（记录 license） |
| 5 | **目标客群描述**（角色+场景一句话） | 全文人称与钩子选择 | 无 → 文章=无的放矢，先问 |
