Illustrative example: FluxPedal Motors and every named owner are fictional; this page proves no product or service capability. Assemble one consistent cargo hub-motor readiness packet before any bounded candidate review. It is for mid-market cargo e-bike OEM or fleet teams evaluating a 48 V repeated-grade application, with bounded load, wheel, duty, electrical, and interface records already available and a path to complete second-round evidence. It is not for consumer replacement shopping, price-only sourcing, final-certified procurement, or projects lacking those records. Use the first round only to mark packet completeness, list missing evidence, and define the next review step; do not recommend or stop a candidate until the complete second-round package is reviewed. This is an engineering-readiness task, not a quote, supplier award, performance proof, final suitability decision, or promise of response time.

## Why wattage-first selection may create avoidable rework

1. An application engineer owns the first readiness review for a loaded, repeated-grade cargo e-bike candidate.
2. When a 20-inch cargo e-bike program needs a hub-motor and controller direction for repeated-duty routes, that engineer may receive a candidate request based mainly on a wattage label.
3. Because the label omits comparable load, wheel, duty, electrical, or interface evidence, Engineering cannot defend the comparison basis.
4. That evidence gap can force Engineering to rebuild the comparison and Quality to revisit the same assumptions.
5. The repeated review may allow a weak or mismatched candidate to enter sample validation before the decision basis is defensible.
6. Therefore, complete one readiness worksheet, identify missing evidence, and define the next review step—not select or reject a candidate from the first-round packet.

**The first decision is packet completeness—not candidate selection.**

## Use five decision blocks before the first review

Compare the five engineering-readiness inputs on one basis: how each input changes packet completeness and the next review step. The page keeps that decision logic in narrow-screen-friendly blocks. Detailed units and examples appear once, in the local worksheet below.

### Establish the load context
Explain how the loaded operating range changes grade and repeated-duty review. If it is missing, hold and request the range; do not infer no-fit.

### Define the rolling geometry
Show how installed wheel and tire geometry changes mechanical demand and fit assumptions. If it is missing, request the installed envelope.

### Describe the repeated-duty event
Separate a short peak event from repeated grade, duration, stops, repetitions, and ambient conditions. If missing, request the bounded event.

### Separate the electrical limits
Keep battery voltage, battery current, and phase current explicitly typed. If missing, request the typed electrical boundary.

### Summarize the mechanical interface
Use a redacted axle, dropout, and brake-interface summary to expose possible incompatibility without controlled drawings. If missing, request the summary and keep the decision open.

**First-round output: packet completeness, missing evidence, and the next review step.**

Candidate-or-stop remains blocked until the complete second-round package is reviewed by the named technical owner.

## What Applications Engineering requests in round two

Round one determines whether the case is reviewable. It does not collect the complete technical-validation package. After the named technical owner accepts the first-round packet, the next request may add:

| Second-round input | How it builds on round one | Why it is needed |
|---|---|---|
| Target speed, controller speed limit, and controller strategy | New input; it does not refine a first-round field | Confirms the speed boundary and control approach required before candidate-or-stop review |
| Detailed duty-cycle, ambient, repetition, and thermal test method | Refines: route grade and repeated-duty profile | Turns the first-round route summary into a reviewable duty and thermal method |
| Exact axle and dropout drawing plus connector, sensor, cable, and controller-interface details | Refines: axle, dropout, and brake interface summary | Turns the first-round interface summary into an exact fit and integration review |
| Target market and vehicle category | New input; it does not refine a first-round field | Defines the regulatory and vehicle-context evidence still required |
| Sample timeline and acceptance criteria | New input; it does not refine a first-round field | Defines the next validation sequence and decision threshold |

These are second-round inputs, not hidden prerequisites for preparing the first-round worksheet. They are prerequisites for any candidate-or-stop direction. The table shows which requests are new and which refine a first-round summary, so the buyer is not asked to resubmit the same information under a different label.

## Candidate or stop: make the boundary visible

Use the complete first- and second-round evidence package to choose the next action—not to manufacture certainty.

### Continue with a candidate direction when

- the first-round worksheet and all five second-round inputs are complete;
- available family-level information shows no observed interface conflict;
- assumptions and unresolved risks are explicit;
- the next validation task has an accountable owner.

### Stop the candidate path when

- an evidenced axle, dropout, or brake incompatibility exists;
- a controller or measured-duty result is outside a supported envelope;
- the requested technical scope is explicitly unsupported.

### Request missing evidence before recommending a candidate

Review the candidate-or-stop boundary only after both rounds are complete and a named technical owner has reviewed the unresolved inputs.

When any required first- or second-round row is incomplete, hold the case and identify the missing evidence. Missing evidence is not proof of no-fit and must not be converted into a disqualification.
