# Operations Logs Index

## 设计结论

- 默认每天一个文件：`YYYY-MM-DD.md`，当天持续追加，不为每个事件单独建文件。
- 每条事件使用 `EVT-YYYYMMDD-####`，只写短事实卡、证据路径、变更结果和下一步，不复制原始对话。
- 每月生成一份 `YYYY-MM-summary.md`，提炼长期结论、已关闭事项、未决风险和需要回写的知识页。
- 原始每日文件永久保留但降为追溯层；目录入口优先展示最近日志、月度摘要和历史月份入口。
- 如果单日日志超过约 200 条事件，或同时维护多个独立 scope，再拆为 `YYYY-MM-DD-mother.md`、`YYYY-MM-DD-<sub-library>.md`。

这套设计把“可追溯”与“可阅读”分开：日志保留事实流水，月度摘要负责压缩，稳定知识只进入 wiki/concepts/playbooks/courses。不会把一条操作记录复制到多个正文页。
