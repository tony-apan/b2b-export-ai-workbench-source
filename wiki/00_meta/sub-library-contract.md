# 子库统一合同

## 目标

用户拿到一个子库后，不需要理解母库结构。用户只需：打开本地 Markdown、让 AI 读取协议和课程地图、复制自己的私有运行区、提供最少来源、审批外部动作、查看真实验收和写回记录。

## 必须包含的文件

| 文件 | 作用 | 验收标准 |
|---|---|---|
| `README.md` | 总入口和完整导航 | 不知道文件名的用户也能找到全部必需资产 |
| `START-HERE.md` | 最短启动路径 | 能直接复制第一条 AI 指令 |
| `COURSE-MAP.md` | 逐课学习路线 | 每课有必读、必交付和通过闸 |
| `MENTAL-MODEL.md` | 稳定业务模型、对象和迁移方法 | 用户能解释底层逻辑 |
| `AGENTS.md` | AI 最高优先级协议 | 写清来源、权限、审批、验证和写回 |
| `INTAKE.md` | AI 先检查再询问缺口 | 不让用户重复填写已有信息 |
| `WORKSPACE-TEMPLATE/` | 可复制的客户私有运行区空模板 | 来源、知识、任务、输出、指标和写回有固定位置 |
| `PLAYBOOK.md` | 端到端流程 | 有输入、动作、输出、闸门、回滚 |
| `TOOLS.md` | 工具选择、安装和适配边界 | 核心方法不绑定单一工具 |
| `TEMPLATES/` | 结构化输入、字段映射、失败和迁移记录 | 字段可直接实例化，关键证据不可省略 |
| `EXAMPLES/` | 虚拟演示 | 明确标注虚构，不能冒充证据 |
| `ADAPTERS/README.md` | adapter 合同 | 核心流程与按钮操作分离 |
| `ADAPTERS/_template.md` | 具体工具适配器强制模板 | 版本、来源、映射、权限、样本、验证、回滚齐全 |
| `QA-CHECKLIST.md` | 源码、任务、迁移、发布四层完成闸 | 不用“文件齐全”冒充业务通过 |
| `SOURCES.md` | 来源、版权和事实边界 | 能追溯，不复制未授权内容 |
| `BRAND.md` | 品牌、Logo、署名和使用限制 | 不由 AI 编造 |
| `CONTACT.md` | 联系、支持和反馈 | 不由 AI 编造 |
| `VERSION.md` | 版本、兼容性和更新入口 | latest-only 可追踪 |
| `WRITEBACK.md` | 学习写回和分流规则 | 客户事实不误回传母库 |
| `MANIFEST.md` | 包含、排除、占位符和 release 状态 | 可以复现发布包和阻断 |


## 子库内部 durable page 规则

子库不是把所有 Markdown 都强行编号。根入口、合同、adapter、模板、来源、验证记录和写回记录保留语义文件名，避免破坏安装和运行入口；需要长期沉淀、跨任务复用的知识页，放入子库 `MANIFEST.md` 声明的 `durable_roots`，默认约定为：

```text
KNOWLEDGE/   概念、对象和稳定判断
PLAYBOOKS/   可重复执行的流程
COURSES/     课程模块和练习
OUTPUTS/     可复用产出与复盘
```

这些页面使用 `id-####-slug.md`，并在元数据中写匹配的 `doc_id`、人话 `description`、`when_to_read` 和 3-8 个 `keywords`。子库独立校验时必须调用母库的 scope validator；因此母库和子库都可以从 `ID-0001` 开始，但不会互相抢号。

## 条件性交付适配器

- `SKILL.md` 不是所有子库的必需文件；只有存在稳定 AI 执行场景、输入输出、权限边界和验收证据时才创建。
- Skill 只负责把子库能力适配给特定 AI 环境，不复制完整知识，也不得覆盖系统、用户项目或宿主 agent 的更高优先级规则。
- 人类操作包、AI Skill 和工具包可以分别发布；注册表和 `MANIFEST.md` 必须声明实际交付形态。
- 不建立与 `sub-libraries/` 平行的第二套 Skill 真源；Skill 源文件留在对应子库，发布时再构建平台适配包。

## 教学原则：授人以渔

统一教学链路：

```text
业务目标 → 输入与数据模型 → 转换规则 → 工具接口
→ 单样本执行 → 真实结果验证 → 失败诊断 → 分层写回
```

每个子库必须提供：

1. **Why**：为什么做和创造什么业务价值；
2. **Model**：不绑定工具的对象、字段、流程、质量闸和权限；
3. **Reference implementation**：一个真实可验证的具体工具链；
4. **Transfer exercise**：迁移到第二工具或相邻业务任务并完成单样本。

按钮、菜单、版本和平台字段留在 `ADAPTERS/`；稳定模型留在 `MENTAL-MODEL.md`、`PLAYBOOK.md` 和模板中。参考实现成功但迁移失败，教学结论仍为 `BLOCK`。

## AI 必须支持的四种模式

| 模式 | 用户说法示例 | AI 必须做什么 |
|---|---|---|
| 建库 | “先了解我们公司和产品” | 读站、读资料、提事实、列冲突、只问阻断缺口 |
| 执行 | “上传这批产品 / 文章” | 使用已有知识和模板，先小样再批量 |
| 审计 | “检查网站有没有问题” | 给证据、严重级别、修复建议，不把猜测写成事实 |
| 复利 | “把这次经验沉淀下来” | 把客户事实、结果、失败和通用改进分流写回 |

## 每个 Module 的统一接口

每个子库必须回答：业务结果、前置知识、可替换工具、结构化输出、人工审批点、成功证据、回滚方式、客户写回和母库升级边界。

## 品牌与占位符规则

发布时需要填充：品牌名、产品或服务名、Logo、官网、联系、支持、更新地址、版权主体和许可证。AI 不得编造。

占位符分两层处理：

- **Draft 源码包**：允许保留故意的 `{{...}}`，但必须在 `MANIFEST.md` 逐项登记，release 状态保持 `BLOCK`；
- **品牌化发布制品**：不允许保留任何 `{{...}}`、测试文字或本地绝对路径。

品牌页还必须说明署名、修改、转售、支持和更新边界。

## 发布闸

子库只有同时满足以下条件才可对外交付：

- 必需文件和包内导航完整；
- 品牌、联系、许可、版本和更新入口明确；
- release artifact 没有占位符、凭据、客户资料、本地路径和私有母库路径；
- 虚拟示例已标注，课程和第三方内容有合法使用边界；
- 至少跑过一次从 intake 到 writeback 的真实参考实现；
- 至少完成一次第二工具或相邻任务迁移，并通过单样本验证；
- 发布者人工确认。

只满足“安全可公开”不等于“课程可交付”。任何关键证据缺失均为 `BLOCK`。

## 版本与分发

默认只交付一个 `latest` 包，同时在 `VERSION.md` 保留版本号和变更摘要。历史版本留在私有母库或发布系统，不把多个相近版本一起塞给用户。源码子库、AI Skill 包、人类文档包和工具包的 release 状态分别记录，不以源码目录存在冒充发布完成。
