## 目标

通过搜索意图、内容集群、技术 SEO 和可转化页面获取长期自然流量和线索；同时把真实搜索语言、需求变化、页面反馈和询盘持续编译进业务知识库。

SEO 在本项目里有双重目标：

1. **增长**：获得可持续的搜索曝光、点击和询盘。
2. **学习**：快速发现市场问题，用页面做假设，再用 Search Console、Analytics、CRM 和销售反馈验证。

## 核心判断：内容从客户问题中来

SEO 的核心载体是内容，但内容的上游是客户问题和搜索意图。客户聊天、询盘、销售电话、客服记录和站内搜索会暴露客户正在经历什么、如何描述问题、使用过什么替代方案、担心什么以及需要什么证据。

聊天内容不能直接等同于搜索词。应按以下链路转换：

`客户语言（真实资料留私有层；虚拟演示明确标注） -> 痛点 -> 任务与购买阶段 -> query hypothesis -> 页面类型 -> 证据与 CTA -> 发布 -> Search Console / 询盘验证`

单次聊天只产生 hypothesis；多次独立重复、真实 query、SERP 和页面转化可以逐步提高置信度。详细方法见 [Search Intent](../../20_concepts/id-0001-search-intent.md) 和 [Customer Voice To Search Intent Template](../../_templates/customer-voice-to-search-intent.md)。

## Operating System

当前 SEO 模块按“官方基线 -> 市场/竞品 -> 关键词/意图 -> 内容差距 -> 技术抓取 -> 页面优化 -> 外链/PR/品牌 -> Search Console 复盘 -> 刷新”的闭环维护。

## Knowledge Writeback Loop

`query / SERP / 客户问题 -> source/raw -> 搜索意图与业务知识 -> 页面假设 -> 发布 -> 数据与询盘 -> 回写 wiki`

| Signal | Immediate Output | Knowledge Writeback |
|---|---|---|
| 新 query / 新说法 | keyword 或 FAQ backlog | `20_concepts`、customer pain、glossary |
| 高展示低点击 | title / promise 测试 | messaging、搜索意图 |
| 高点击低询盘 | CTA / offer / ICP 检查 | offers、ICP、buyer journey |
| 有效询盘与销售问题 | 新页面或案例 brief | objections、proof、product facts |
| 排名或 SERP 变化 | refresh 任务 | 竞品判断、过时知识、open questions |

详细规则见 [Knowledge Compounding System](../../00_meta/knowledge-compounding-system.md)。

## Backlogs

| Backlog | Purpose | Source |
|---|---|---|
| Keyword backlog | 待评估关键词 | GSC、SEMrush、客户语言、销售反馈 |
| Content gap backlog | 和竞品相比缺失的页面/主题 | 竞品页面和关键词差距 |
| Technical SEO backlog | 抓取、索引、重定向、薄内容、schema、hreflang 等问题 | GSC、crawl、页面检查 |
| Refresh backlog | 需要更新的旧内容 | GSC impression/click/position、业务变化 |
| Authority backlog | PR、真实第三方证据、合作、目录和案例机会 | proof library、PR、伙伴资料 |
| Conversion backlog | 有流量但不转化的页面 | Analytics、CRM、销售反馈 |

## Search Console Fields

| Field | Use |
|---|---|
| Query | 判断真实搜索需求和语言 |
| Page | 判断哪个页面承接需求 |
| Impressions | 判断展示机会 |
| Clicks | 判断流量获取 |
| CTR | 判断标题/摘要/意图匹配 |
| Average position | 判断排名趋势，不单独作为成功指标 |
| Indexing reason | 判断未收录或异常原因 |
